中小型企业智能财务报销系统设计与实现

一、系统概述
本系统面向中小型企业财务报销场景，围绕“员工发起、财务审批、预算控制、统计分析”构建完整闭环。系统采用前后端分离架构，集成OCR识别与票据验真能力，实现发票自动识别、报销流程标准化、预算额度自动扣减、审批意见可追踪等功能。

二、建设目标
1. 降低人工录入成本：发票字段自动识别并回填。
2. 规范报销流程：按业务类型分场景提交，状态流转清晰。
3. 强化预算约束：提交即校验、通过即扣减、撤销即回退。
4. 提升财务效率：会计端集中审批，支持同意/拒绝/撤回。
5. 支持管理决策：个人与部门维度统计可视化展示。

三、技术架构
1. 前端
- Vue3 + Vue Router
- Element Plus
- Axios
- ECharts

2. 后端
- Django + Django REST Framework
- MySQL
- 百度OCR接口（增值税发票识别/增值税发票验真）

3. 数据层
- 关系型数据库MySQL
- Django migrations维护结构演进

四、系统角色与权限
1. 员工（employee）
- 发票上传与验真
- 新建报销/暂借款/酬金申报/日常报销/国内差旅报销
- 草稿修改、删除、提交
- 已提交撤销、被拒后修改重提
- 查看个人历史、状态与审批回复

2. 会计员（accountant）
- 查看全员待审票据
- 审批同意（进入历史功能票据）
- 拒绝并填写回复（例如缺少材料）
- 撤回审批（退回草稿并回退预算）
- 查看历史审批票据

五、核心业务模块
1. 认证与个人中心模块
- 注册/登录
- 个人信息维护（姓名、电话、部门、密码）
- 角色识别并动态展示菜单（员工端/会计端）

2. 发票验真与识别模块
- 上传发票图片/PDF
- OCR提取发票代码、号码、日期、金额、买卖方信息
- 重复票据识别（发票指纹）
- 生成6位票据编码用于后续报销关联

3. 报销申请模块（四大业务）
- 日常报销业务：有发票流程，填写摘要、预算项等并提交
- 国内旅费业务：专用模板，支持交通住宿分项、天数联动、自动合计
- 暂借款业务：无发票流程，独立借款字段与预算项
- 酬金申报物业：无发票流程，复用借款链路并按申报场景约束字段

4. 票据夹与状态流转模块
- 状态：草稿、已提交、历史功能票据（审批通过）、已拒绝
- 草稿：可修改、删除、提交
- 已提交：可撤销
- 已拒绝：可修改、提交、删除、撤销（恢复草稿）
- 拒绝单据展示会计回复，便于申请人整改

5. 会计审批模块
- 待审列表（仅已提交）
- 票据详情查看（含发票关键字段与原件预览）
- 审批动作：同意、拒绝（必填回复）、撤回
- 历史审批列表：查看已审批结果和回复记录

6. 预算管理模块
- 预算模板解析并生成预算项列表
- 报销/借款提交时按预算项扣减额度
- 撤销或驳回时回退额度
- 预算台账记录总额、已用、可用、占比

7. 统计分析模块
- 个人报销统计（柱状图+饼图）
- 部门报销统计（柱状图+饼图）
- 统计口径覆盖有效业务状态（已提交与已通过）

六、数据库设计（最终版）
当前系统包含5张核心表：
1. employee（员工信息）
2. invoice（发票与OCR结果）
3. reimbursement（有发票报销单）
4. temporary_loan_application（暂借款/酬金申报）
5. budget_quota（预算台账）

主要关系：
- employee 1:N invoice
- employee 1:N reimbursement
- invoice 1:1 reimbursement
- employee 1:N temporary_loan_application
- budget_quota与业务单据通过budget_item业务字段关联

七、关键实现逻辑
1. 发票去重逻辑
- 通过发票关键字段计算指纹，验真成功票据不允许重复入库。

2. 预算扣减/回退逻辑
- 提交成功时扣减预算。
- 撤销或拒绝时回退预算，避免占用错误。

3. 审批回复闭环
- 会计拒绝必须填写回复。
- 员工可在票据夹查看回复并修改后重新提交。

4. 前端动态表单逻辑
- 按业务大类切换不同模板。
- 国内旅费按“日费率*天数+交通项”自动汇总金额。

八、系统操作流程（用户视角）
1. 员工端
- 登录 -> 发票验真 -> 报销申请（选业务类型）-> 保存草稿或提交
- 在票据夹中持续跟踪状态
- 若被拒绝：查看会计回复 -> 修改 -> 再提交

2. 会计端
- 登录审批中心 -> 查看待审票据 -> 查看详情核验
- 选择同意/拒绝（填写原因）/撤回
- 在历史审批模块查看处理记录

九、系统可用性与可维护性
1. 可用性
- 业务流程明确，关键路径具备错误提示和状态反馈。
- 核心动作可逆（撤销、回退预算）降低误操作成本。

2. 可维护性
- 前后端分离，模块边界清晰。
- 数据结构通过migrations持续演进，便于版本管理。
- 关键业务规则（预算、审批、状态）集中在后端接口层实现。

十、项目成果与价值
1. 提升报销处理效率，减少人工录入和反复沟通。
2. 通过预算控制与审批闭环强化财务合规。
3. 通过统计可视化支撑部门与个人费用分析。
4. 具备中小企业场景下“可落地、可扩展、可维护”的应用价值。

十一、后续优化方向
1. 将国内旅费细分项从remark文本进一步结构化入库。
2. 增加审批流配置（多级审批、金额阈值路由）。
3. 引入操作日志与审计报表。
4. 支持导出月度对账单、预算执行报表。
